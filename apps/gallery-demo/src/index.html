How it works

Three moves, from mint to proof

No smart contract and no public index. The chain holds a small seal, and the holder carries the rest.

1

Seal it

The artwork and its metadata are encrypted once and stored off-chain. Zcash receives only a 512-byte seal, plus tags that stop the same slot being minted twice.

2

Hand it over

To transfer, the seller re-wraps a 32-byte key for the buyer and adds one step to the object's proof. The media is never re-uploaded, however large it is.

3

Show only what you choose

A per-object viewing key reveals one item to a gallery or a ticket gate. A zero-knowledge proof shows you own it. The rest of your wallet stays dark.

Architecture

Four folds, and where each one stands

The cryptography runs for real. Settlement is simulated in memory until it is wired to a Zcash node.

01 · Identity & scarcity Implemented

An identity Zcash already understands

Every object gets a ZIP 227 asset identity at mint, so it can later become a native Zcash Shielded Asset without changing its ID. A range proof ties each slot to its collection's supply cap.

Until ZSA activates, global uniqueness relies on a public mint-nullifier log.

BLAKE2b-512 AssetDigest · Pallas AssetBase · IssuanceCapCircuit
02 · Out-of-band wrapping Implemented

Move the key, not the file

Payloads are encrypted once. A transfer re-wraps only the 32-byte data key for the next holder, so handing over a large artwork costs the same as a small one.

Post-quantum hybrid wrapping (ML-KEM-768) is a design target, not built.

ChaCha20-Poly1305 · ephemeral Pallas ECDH · HKDF-SHA256
03 · Recursive lineage Implemented

One proof for the whole history

Mints, transfers, royalty steps, ticket check-ins and upgrades are separate small circuits that fold into one proof. A verifier checks the latest proof and never replays the past.

Passing a proof to the next owner is not yet unlinkable in upstream Ragu.

tachyon-zcash/ragu · 10 Step<Pasta> circuits · no trusted setup
04 · Settlement Simulated ledger

Orchard today, ZSA and Tachyon next

Stage I anchors seals in Orchard memos. Stage II burns a seal into a native ZSA note, co-signed by a 2-of-3 committee. Stage III moves to Tachyon's 32-byte commitments.

All three ledgers run in memory. Not yet connected to zebrad or lightwalletd.

ZIP 302 memo codec · MigrationCircuit · threshold Schnorr

Use cases

Five fillings, one wrapper

A profile is a set of rules for one kind of object. All five share the same wrapper: one seal, one viewing key and one proof format. So a single object can carry steps from several of them.

NFT1Ragu step: RoyaltyCircuit

Art & collectibles

An artist drops 100 pieces. Collectors trade them with no public owner list, and show a single piece to a gallery when they choose to.

Stays private
The artwork file, who holds it, and everything else in the holder's wallet.
Can be proven
The piece belongs to the collection, its slot is within the cap, and each sale carried a royalty receipt.
TKT1Ragu step: TicketCheckInCircuit

Event tickets

A venue sells tickets that can be resold privately. At the door each ticket checks in once, and a copy of it cannot get in again.

Stays private
Who bought the ticket, who they bought it from, and what else they hold.
Can be proven
The ticket is genuine for this event and has not been used. Check-in publishes a one-time nullifier.
CRD1Host-side rules

Credentials

A university or a DAO issues a diploma or membership bound to one holder.

Stays private
The holder's identity and their other credentials.
Can be proven
Who issued it and that it has not been revoked. It cannot be transferred.
GAM1Ragu step: UpgradeCircuit

Game items

A blade gains XP and levels up as it is used. Each upgrade folds into the same proof as its trades.

Stays private
The player's inventory and play history.
Can be proven
The item's current state follows from its recorded upgrades.
RWA1Host-side rules

Real-world deeds

A property deed changes hands only between parties who hold a valid compliance credential.

Stays private
The parties and the terms of the transfer.
Can be proven
The recipient holds a CRD1 credential and a notary attested the transfer.

NFT1, TKT1 and GAM1 have their own step circuits today. CRD1 and RWA1 rules run as host-side checks and are candidates for circuits later.

Get started

Quickstart & Technical Documentation

Needs Rust 1.97 or newer. The first build compiles Ragu and takes a few minutes.

Step 1

Run the test suite

Checks the ZIP 227 and ZIP 302 vectors, all ten Ragu circuits and the Studio API.

$ cargo test --workspace --offline
Step 2

Start Studio locally

Serves this site, the docs and the interactive workbench at 127.0.0.1:8080.

$ cargo run -p zyoza-gallery-demo
